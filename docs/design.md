# 디자인 규칙

UI를 바꾸기 전에 읽는다. **지금 디자인 규칙의 원본은 이 파일이다.** 결정 기록([0009](decisions/0009-ui-plain-language.md)·[0010](decisions/0010-tray-and-dashboard.md)·[0011](decisions/0011-visual-design.md)·[0015](decisions/0015-dashboard-daily-activity.md))은 왜 그렇게 정했는지의 기록이다. 규칙을 바꾸면 이 파일을 고친다.

## 1. 화면 역할 (0010)

- **트레이(팝오버)는 결론만.** 숫자를 읽는 순간 뜻이 통해야 한다. 통계·근거·항목 목록처럼 해석이 필요한 것은 대시보드에 둔다.
- 트레이에서 모르는 값은 "—"로 채우지 않고 줄을 숨긴다. `~`와 툴팁 말고는 트레이에 설명 문장을 두지 않는다.
- **대시보드는 자세히 전부.** 위에 일일 활동(링·최근 7일 줄·시간대 그래프, 0015), 아래에 에이전트별 상세 카드. 자세히는 접지 않는다. 너비 900px 이상에서 2열.
- 설정 화면은 팝오버 안에 있다. html 15px 기준 rem을 쓴다(`text-sm` ≈ 13px, `text-xs` ≈ 11px).

## 2. 말 (0009)

- 화면 용어는 0009 "용어" 표를 따른다. 새 용어는 표에 먼저 넣고 사용자에게 확인한다.
- 예상 값은 숫자 앞에 `~`, 정확(측정) 값은 아무것도 붙이지 않는다. 값의 `title`은 "예상: 기록으로 계산한 값" / "정확: 측정한 값". 기본 화면에 "실측·추정·추론" 글자를 쓰지 않는다.
- `%p` 대신 `%`. 시간은 `4h 35m`. "평균" 대신 "보통"(중앙값).
- 영어 화면 용어는 0009 "English terms" 표: Startup context, "N% of the window", Estimated / Measured, Tokens per 1% of the limit, 5-hour window, Weekly window, credits(Kiro). 영어 화면에는 한글을 한 글자도 두지 않는다(언어 선택의 "한국어"도 영어 화면에서는 "Korean").

## 3. 위계 (0009·0011)

- 한 덩어리 = 제목 → **큰 값 한 줄**(숫자 하나가 주인공) → 막대 → 회색 설명 한 줄(`text-muted-foreground`). 위 두 단계만 보고도 뜻이 통해야 한다. 자세히는 대시보드에만.
- 숫자는 모두 `tabular-nums`.

## 4. 색 토큰 (0011)

- `index.css`의 `:root`·`.dark`: shadcn neutral 토큰 + `--agent-claude`(테라코타)·`--agent-codex`(에메랄드)·`--agent-kiro`(보라)·`--warn`(호박). 새 색은 결정 기록 없이 더하지 않는다.
- 에이전트 색은 `agent-metrics.tsx`의 `AGENT_COLOR` 하나로 쓴다(막대·다이얼·탭·링·그래프).
- 남은 %가 `lowPercent` 이하면 에이전트 색 대신 `destructive`. 부족·넘침은 `--warn`.
- `destructive`(빨강)는 `lowPercent` 이하와 진짜 실패에만 쓴다. 설치·로그인·허용처럼 사용자가 할 일은 `text-muted-foreground` + `Info` 아이콘이다(`StateText kind="setup"`). 요일(일요일 포함)은 빨갛게 하지 않는다.

## 6. 공통 규칙 5개 (모든 화면, 2026-11-09 채택)

Meta Astryx [Design-Conventions](https://github.com/meta/astryx/wiki/Design-Conventions)에서 화면 모습을 바꾸지 않는 것만 골라 요약했다.

1. **간격으로 묶는다.** 관련 있는 것은 좁게, 묶음 단계가 올라갈수록 넓게: 라벨→값 < 줄끼리 < 카드 안 묶음끼리 < 카드끼리. 안쪽 간격이 바깥 간격보다 넓으면 안 된다. 카드 안에 카드를 넣지 않는다. 묶음은 간격이나 구분선으로 나눈다.
2. **모서리는 동심원.** 안쪽 radius = 바깥 radius − 그 사이 여백. 결과가 0 이하면 각지게 둔다.
3. **색은 뜻만큼만.**
   - 글자와 배경의 대비는 WCAG AA: 본문 4.5:1, 큰 글자·막대·아이콘 3:1. 회색 보조 글자와 반투명(vibrancy) 배경 위도 포함.
   - 상태를 색만으로 알리지 않는다. 글자·아이콘·모양을 함께 쓴다(예: `--warn`색 + "N% 부족").
   - 한 화면에 강조 버튼은 하나. 나머지는 보조 모양.
   - 다크에서 겹친 면(배경·카드·회색 칸)은 밝기가 달라야 칸 경계가 보인다. 지금 `.dark`의 background 0.145 / card 0.205 / muted 0.269를 유지한다.
4. **상태를 빠짐없이.** 누를 수 있는 것은 hover·focus-visible·active·disabled 모양을 정한다. 값 칸은 불러오는 중·빈 값·오류 모양을 정한다(트레이는 줄 숨김, 1절). 같은 상태는 어디서나 같은 모양이다. 새 모양을 만들기 전에 있는 것을 다시 쓴다.
5. **움직임은 뜻이 있을 때만.** 장식 애니메이션은 넣지 않는다. `transform`·`opacity`만 움직인다(width·height·margin 금지). `prefers-reduced-motion`이면 끈다(`motion-reduce:`). 상시 animation loop는 `AGENTS.md` 성능 원칙대로 금지.

가져오지 않은 것: 본문 12px 이상, 컨트롤 높이 28/32/36, 글자 단계 1.25배 이상, Astryx 라이브러리. 2026-11-09 실험(라이브러리 + 규칙 전부)에서 트레이가 커지고(개요 483 → 552px) 화면 코드가 1.86배가 되어 사용자가 버렸다.
