kcal은 무엇을 어디서 읽고, 언제 무엇을 바꾸나

kcal은 메뉴 막대(Windows는 트레이) 앱이다. Claude Code·Codex·Kiro의 남은 사용 한도와, 에이전트가 첫 메시지 전에 싣는 토큰(시작 컨텍스트)을 보여 준다. 그리고 안 쓰는 플러그인을 사용자가 확인하면 대신 꺼 준다.

30초 설명 (남에게 이렇게 말하면 된다)
  1. 한도는 Claude Code가 이미 저장해 둔 로그인 토큰을 빌려 읽어서 Anthropic 사용량 주소에 5분마다 묻는다. 토큰은 저장하지도 갱신하지도 않는다.
  2. 시작 컨텍스트는 Claude Code가 남긴 세션 기록에서 실제로 보낸 요청의 크기를 잰다. 기록이 없는 것은 파일 크기로 추정하고 ~를 붙인다.
  3. 끄기는 사용자가 바뀔 줄을 미리 보고 확인한 뒤에만 한다. 원본 옆에 백업을 만들고 값 하나만 바꾸며, 앱 안에서 되돌릴 수 있다.

2왜 이렇게 만들었나

질문마다 실제 파일·명령·장면을 먼저 보여 주고 설명한다.

① 남은 한도는 어떻게 아나?

Claude Code는 로그인하면 토큰을 맥 키체인에 저장한다. kcal은 그 토큰을 이렇게 꺼낸다.

/usr/bin/security find-generic-password -s "Claude Code-credentials" …

그 토큰을 붙여 아래 주소에 "내 한도 얼마 남았어?"라고 묻는다. 5시간·주간 한도와 초기화 시각이 돌아온다.

GET https://api.anthropic.com/api/oauth/usage

토큰은 읽기만 하고 저장하지도, 갱신(refresh)하지도 않는다. kcal이 토큰을 갱신하면 Claude Code가 들고 있던 토큰이 무효가 돼 Claude Code가 로그아웃될 수 있기 때문이다. 토큰이 만료됐거나 요청이 실패하면 로컬 기록으로 대신 보여 주고 "N분 전 기준"이라고 표시한다.

근거: 결정 0003 "한도 출처", usage/sources.rs

② 왜 5분마다 묻나? 다른 데는 왜 타이머가 없나?

규칙 : 타이머 금지         이유: 메뉴 막대에 늘 떠 있는 앱이라, 쉬는 동안 CPU·배터리를 먹으면 안 된다
예외 : 한도 조회 타이머 하나  이유: 한도는 Anthropic 서버에만 있고, 바뀌어도 알려 주지 않는다 → 물어봐야만 안다

그래서 Rust 쪽 타이머 하나만 5분마다(Kiro는 10분) 묻는다. 나머지(시작 컨텍스트, 환율, 지표)는 내 Mac에 있는 파일이라 화면이 값을 달라고 할 때 계산하면 된다. 타이머가 필요 없다.

평소:       5분 → 5분 → 5분
너무 자주 물어 거절(429)되면: 서버가 "몇 초 뒤에 다시"(Retry-After)를 주면 그대로,
                              안 주면 10분 → 20분 → 40분 → 60분(최대)

화면이 값을 달라고 하면 캐시에 있던 옛 값을 먼저 주고, 오래된 값이면 뒤에서 한 번 다시 계산해 이벤트로 보낸다.

근거: 결정 0003 "주기 측정", usage/schedule.rs, cache.rs

③ 시작 컨텍스트는 어떻게 재나? 왜 어떤 숫자에만 ~가 붙나?

갈림길은 "그 항목이 실제로 보낸 요청 안에 따로 적혀 있나"다.

항목어디서 재나표시
시스템 프롬프트, 내장 도구, MCP 도구보낸 요청 안에 따로 적혀 있다 → 그 크기를 잰다측정
CLAUDE.md, 규칙, 스킬, 에이전트 정의요청 안에서 구분이 안 된다 → 파일 크기를 잰다~ 추정

"보낸 요청"은 세션 기록 파일(~/.claude/projects/…/*.jsonl)에 남는 이런 줄이다. Claude Code 2.1.300부터 생겼다.

{"type":"api-request-shape", "shape": { system: [...], tools: [...] } }

둘 다 크기(바이트)를 4로 나눠 토큰으로 바꾼다. 이 줄의 크기만 보고, 같은 파일의 메시지 원문 줄(api-request-blob)은 열어 보지 않는다.

Claude Code가 2.1.300보다 오래됐거나 아직 세션을 한 번도 안 열었으면 이 줄이 없다. 그때는 전부 파일로만 세고 합계에 "estimate only"(예상만)를 붙인다.

근거: 결정 0005, context/shape.rs, README "무엇을 측정하나"

④ "한도 1% = 토큰 몇 개"(환율)는 어떻게 아나?

Anthropic은 이 값을 알려 주지 않는다. 그래서 kcal이 두 기록을 맞대어 추정한다.

kcal 자기 기록 limit-history.jsonl : 언제 한도가 몇 %였나 (시각과 %만)
Claude Code 세션 기록             : 그 5시간 동안 토큰을 얼마나 썼나

5시간 구간이 여러 개 쌓이면 "이만큼 썼더니 몇 % 올랐다"를 여러 번 본 셈이다. 그 구간들에 가장 잘 맞는 "1%당 토큰 수"를 계산한다(음수가 나오지 않게 하는 최소제곱 계산, NNLS). 기록이 충분하지 않으면 숫자 대신 "기록 모으는 중"을 보여 준다. 추정값이라 ~가 붙는다.

근거: 결정 0006, rate/

⑤ 진단은 무엇을 끄라고 하나? 기준은?

최근 30일 Claude Code 세션 기록에서 에이전트가 도구를 부른 줄을 센다. 예를 들어 이런 이름이 나오면 그 MCP 서버를 한 번 쓴 것이다.

"tool_use" 이름: mcp__plugin_context7_context7__query-docs  → context7 플러그인 1회

세션이 10개 이상 있는데 한 번도 안 쓴 것만 끄라고 제안한다. 세션이 10개보다 적으면 "알 수 없다"고 하고 제안하지 않는다. 몇 번 안 써서 꺼도 되는지 판단할 근거가 없기 때문이다. Codex·Kiro는 kcal이 사용 횟수를 볼 수 없어서 제안하지 않는다. 대신 사용자가 직접 끌 수는 있다. 30일, 10세션은 설정에서 바꿀 수 있다.

근거: 결정 0022, coach/usage.rs

⑥ "끄기"를 누르면 실제로 무슨 일이 생기나?

예: Codex 플러그인 하나를 끈다. 먼저 바뀔 줄을 보여 준다.

~/.codex/config.toml  [plugins."some-plugin"]
- enabled = true
+ enabled = false

확인을 누르면 순서대로 이렇게 한다.

1. 미리보기 때 본 파일이 지금도 그대로인지 확인 (아니면 거부)
2. 원본 옆에 백업: config.toml.kcal-20261128T091500123Z.bak
3. 같은 폴더 임시 파일에 쓰고 이름을 바꿔 넣기 (반쯤 쓴 파일이 안 보이게)
4. 적용 기록 coach-log.jsonl에 한 줄: 언제·무엇·백업 위치·바꾼 뒤 파일 지문(해시)

값 하나만 바꾼다. 섹션을 만들거나 지우거나 순서를 바꾸지 않는다. 파일 모양이 예상과 다르면(같은 섹션이 두 번 등) 고치지 않고 거부한다. 에이전트는 시작할 때 설정을 읽으니, 실행 중이면 다시 시작해야 반영된다.

근거: 결정 0014, coach/edit.rs, coach/mod.rs

⑦ 되돌리기가 왜 거부될 때가 있나?

이런 장면을 생각해 보자.

10:00 kcal이 플러그인 A를 끔 (백업 = 10:00 직전 파일)
10:30 내가 같은 파일에 플러그인 B 설정을 새로 추가
11:00 kcal "되돌리기" → 백업을 그대로 덮으면? → 10:30에 추가한 B 설정이 사라짐

그래서 kcal은 되돌리기 전에 지금 파일의 지문이 10:00에 자기가 쓴 직후 지문과 같은지 본다. 다르면, 다른 줄이 바뀌었더라도 되돌리지 않는다. 대신 백업을 직접 되살리는 명령을 보여 준다. 사람이 보고 판단하라는 뜻이다.

cp ~/.codex/config.toml.kcal-20261128T091500123Z.bak ~/.codex/config.toml

같은 이유로 ⑥의 1번(미리보기와 적용 사이에 파일이 바뀌면 거부)이 있다. 에이전트가 실행 중에 쓴 변경을 덮지 않으려는 것이다.

근거: 결정 0014, coach/mod.rs 되돌리기

⑧ Claude Code의 MCP 서버는 왜 직접 못 끄나?

Claude Code의 MCP 설정은 ~/.claude.json에 있다. 그런데 이 파일은 Claude Code가 실행 중에 계속 다시 쓴다. kcal이 값을 바꿔도 Claude Code가 자기가 들고 있던 내용으로 덮어 버릴 수 있다. 그래서 kcal은 이 파일에 쓰지 않고 "Claude Code에서 /mcp로 끄세요"라고 안내만 한다. 플러그인(~/.claude/settings.json의 enabledPlugins)은 kcal이 끌 수 있다.

근거: 결정 0014

⑨ 내 대화 내용과 토큰은 어디로 가나?

로그인 토큰   → api.anthropic.com 한 곳으로만 (Codex 켜면 chatgpt.com)
대화 본문     → 어디에도 안 남김. 숫자·이름·횟수만 꺼냄
kcal 서버     → 없음. 텔레메트리·자동 업데이트도 없음
예외          → "Claude 넘기기" 버튼: 누를 때만, 지침 파일 하나를 내 Claude Code로 보냄

코드에서도 막는다. 토큰은 Secret이라는 타입에만 담는다. 이 타입은 화면·로그·오류 메시지로 찍으려 하면 값이 가려진다. 실패한 응답 본문도 오류 메시지에 넣지 않는다. 화면(웹뷰)은 CSP 설정으로 kcal 내부 통신만 할 수 있다. 직접 확인하는 명령: git grep -nE 'https?://' -- src src-tauri/src

3깨지면 어디부터 보나

증상먼저 볼 곳
한도가 안 나오거나 "N분 전 기준"토큰을 못 읽었거나 사용량 요청이 실패했다(만료, 거절). Claude Code에 다시 로그인해 본다. 코드는 usage/sources.rs(읽기·요청), usage/schedule.rs(간격).
시작 컨텍스트에 "estimate only"측정할 api-request-shape 줄이 없다. Claude Code 2.1.300 이상에서 세션을 한 번 열면 생긴다. 코드는 context/shape.rs.
진단이 "알 수 없다"며 제안을 안 함최근 30일 세션이 10개 미만이다. 정상이다. 기준은 설정, 세는 코드는 coach/usage.rs.
"끄기"가 거부됨미리보기 뒤에 파일이 바뀌었거나 파일 모양이 예상과 다르다. 거부 이유 문장이 그대로 화면에 나온다. 코드는 coach/edit.rs.
되돌리기가 거부되고 cp 명령이 나옴kcal이 쓴 뒤 그 파일이 바뀌었다(⑦). 백업과 지금 파일을 비교해 보고 cp를 쓸지 정한다.
껐는데 숫자가 그대로에이전트를 다시 시작해야 반영된다. 시작 컨텍스트 측정값은 다음 세션의 요청에서 바뀐다.
환율이 계속 "기록 모으는 중"5시간 구간 기록이 부족하다. 앱을 켜 둔 채 며칠 쓰면 쌓인다. 코드는 rate/.
