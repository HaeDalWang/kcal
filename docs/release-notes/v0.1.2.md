New features and fixes since v0.1.1. To update, run the install line again.

```sh
curl -fsSL https://raw.githubusercontent.com/HaeDalWang/kcal/main/install.sh | sh
```

Or download `kcal-macos-universal.dmg` below. Still unsigned (ad-hoc signed only); see [Install](https://github.com/HaeDalWang/kcal#install) for the first-launch step. Check a download with `shasum -a 256 -c kcal-macos-universal.dmg.sha256`.

## New

- Why the limit burned: the dashboard's weekly summary compares the last N days with the N days before for Claude and Codex: share of input tokens from automated runs (`claude -p`, `codex exec`), share per model, and Codex tokens per 1 % of the limit. For Claude, it points to Claude Code `/usage` for more detail.
- Per-model weekly limits, Claude extra usage, and Codex reset passes.
- The dashboard Usage and Checks tabs have an agent picker.
- Diagnose lists personal and project skills one row each.
- MCP: proposals to turn a server on for one project only (Claude and Codex), and MCP servers declared by enabled Codex plugins are counted.

## Fixed

- Claude extra usage amounts are scaled correctly.
- Updating no longer triggers a macOS Automation prompt to quit the running kcal.
- API key users are told there is no limit to show, instead of being asked to sign in.
- Codex: compressed rollouts are read when counting compactions; a corrupt archive cannot exhaust memory; trusted projects match across Windows path separators.
- A symlink planted at the backup name is refused; hidden-card ids of removed checks are pruned.
- Reason text can be selected; the first-run guide no longer shows twice.
- Faster: Codex rollouts are reread only after they change, and uncached Codex and Kiro logs are parsed on up to 4 threads.
