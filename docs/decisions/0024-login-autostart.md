# 0024. 로그인 시 자동 시작

- 상태: 제안(사용자 결정 대기)
- 날짜: 2026-11-17
- 앞선 결정: [0020](0020-unsigned-macos-release.md) 서명 없는 macOS 릴리스, [0003](0003-product-scope.md) 범위
- 범위: 로그인하면 kcal이 저절로 켜지게 할지, 한다면 어떻게 할지. 코드는 이 기록으로 바꾸지 않는다.

## 문제

지금은 README FAQ("Does it start at login?")가 macOS 시스템 설정 → 로그인 항목에 사용자가 직접 추가하라고 안내한다. kcal은 메뉴 막대에 계속 떠 있는 앱(`ActivationPolicy::Accessory`, `lib.rs:90`)이라 켜 두는 것이 전제인데, 재부팅할 때마다 손으로 켜야 하면 쓰임이 줄어든다. 백로그("로그인 시 자동 시작")가 앱 안 자동 시작은 의존성·capability가 늘어 결정 기록이 필요하다고 남겼다.

현재 상태(확인됨, 이 저장소 읽음): `src-tauri/Cargo.toml`에 autostart 의존성 없음. `capabilities/default.json`은 `core:default`만 허용. 설정 패널 스위치는 아직 없다(백로그·AGENTS.md가 "설정 패널 계획"만 언급).

| capability | 없음 | `autostart:default`(= `allow-enable`·`allow-disable`·`allow-is-enabled`)(출처 2). 프론트 JS 패키지를 쓰면 창이 이 권한을 갖는다. Rust에서만 `ManagerExt::autolaunch()`로 부르고 `ipc.ts` 래퍼 command를 두면 capability 추가 없이 가능(추정: 플러그인 command는 프론트가 부를 때만 권한 검사, 확인 = 빌드해서 capability 없이 Rust 호출) | 없음(자체 command는 `core:default` 범위) |

## 추천: B (`tauri-plugin-autostart`), 기본값은 꺼짐, 스위치는 설정 패널에

- 이유 1: OS별 등록·해제·상태 확인을 공식 플러그인이 이미 하고 있다(단순성 사다리 2·5단). C는 같은 일을 직접 유지해야 하고 SMAppService는 미서명에서 되는지 모른다.
- 이유 2: 의존성이 `auto-launch` 한 줄 수준이다(출처 1). 설치 크기 영향은 모름이지만 크지 않을 것으로 추정한다. 확인 = 추가 전후 release 바이너리 크기 비교.
- 이유 3: 자동 시작은 사용자가 명시적으로 켜는 동작이어야 해서 기본값은 꺼짐, 켠 상태는 OS(plist·Run 키)가 진실이라 settings에 중복 저장하지 않는다.
- macOS는 `MacosLauncher::LaunchAgent`(플러그인 기본값)를 쓴다. `AppleScript`는 System Events 자동화 권한 창을 띄울 수 있어(추정) 피한다.
- 권한은 프론트가 플러그인을 직접 부르지 않고 `ipc.ts` 래퍼 + Rust command가 `autolaunch()`를 부르는 구조를 우선 시도한다(AGENTS.md IPC 규칙). 이게 안 되면 `capabilities/default.json`에 `autostart:default` 한 줄을 추가한다.
- A로 충분하다고 판단하면 이 기록은 "기각, README 안내 유지"로 닫는다. 로그인 시 자동 시작 요구가 실제로 없다면 A가 가장 작다.

## 구현할 때 확인할 것 (아직 안 함)

1. 미서명 릴리스 설치본에서 켜고 재로그인해 실제로 뜨는지(macOS). Gatekeeper가 막는지 포함.
2. 앱 삭제 뒤 plist 잔여물, Windows 제거 뒤 Run 값 잔여물.
3. 앱을 `/Applications` 밖(예: `~/Downloads`)에서 켜면 그 경로가 plist에 박히는 문제. 설치 경로가 `/Applications`가 아니면 스위치를 막거나 경고할지.
4. README FAQ를 "설정에서 켠다"로 고치고 백로그 항목 닫기.
5. 결정 시 `Cargo.toml`·`lib.rs`·`ipc.ts`·설정 패널·번역(`ko`/`en`)·테스트를 같은 작업에서 고친다(0014 IPC 규칙).
