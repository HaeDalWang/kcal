# 0017. 최적화 틀: 처방 유형·처방 카드·개인 기준

- 상태: 채택(틀 + 방향 결정). 구현은 아래 "첫 점검 1차 구현 (2026-11-07)"부터. 처방을 하나씩 넣을 때마다 이 틀에 붙이고, 틀이 모자라면 이 문서를 고친다.
- 날짜: 2026-11-06
- 앞선 결정: [0003](0003-product-scope.md) "5. 코칭", [0014](0014-coaching.md) 코칭 스위치, [0016](0016-health-compare.md) 처방 효과

## 문제

0014 "진단하기"는 켜진 플러그인·MCP를 토큰 큰 순으로 끄자고 제안한다. 사용자 입장에서는 "이걸 왜 꺼? 나 쓰는 건데"라는 의문이 남는다(사용자 지적 2026-11-06).
헬스 앱에 빗대면 목표가 모두 "몸짱"이 아니고, 몸짱의 기준도 사람마다 다르다. 토큰을 덜 쓰는 것이 무조건 좋은 게 아니다.

최적화 방법은 많고 성격이 서로 다르다. 설정 위치 옮기기, 중복 제거, 프롬프트 대신 설정 쓰기, 사용 패턴에 맞춘 추천값, 끄기가 모두 여기에 든다.
처음부터 다 만들 수는 없다. 그래서 틀을 먼저 정하고 처방을 하나씩 채운다. 그래야 나중에 고칠 일이 적고, 새 아이디어가 어느 칸에 들어가는지 바로 보인다.

## 원칙

1. **사용자가 잃는 것으로 나눈다.** 쓰던 기능이 그대로 남는 변경은 "최적화"다. 기능이 줄어드는 변경은 "끄기"다. 둘은 다른 화면, 다른 근거 기준을 쓴다.
2. **기준은 사용자가 정한다.** 추천 순서와 문구는 사용자가 고른 목표(아래 "개인 기준")를 따른다. "나 이거 써"로 고정한 항목은 끄자고 제안하지 않는다.
3. **근거는 출처와 날짜를 붙인다.** 에이전트 동작에 기대는 처방(설정 키, 로딩 방식)은 공식 문서 URL과 확인 날짜, 에이전트 버전을 함께 기록한다. 기억에 기댄 처방은 넣지 않는다. 버전이 바뀌면 다시 확인한다.
4. **효과는 잰다.** 적용한 처방은 0016 처방 효과(전후 비교)에 들어간다. 잴 수 없는 처방은 "효과 측정 안 됨"으로 표시한다.

## 처방 유형 (분류 축)

| 유형                 | 뜻                                                     | 사용자가 잃는 것               | 예                                                                                                                        |
| -------------------- | ------------------------------------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **A. 위치 옮기기**   | 늘 실리는 것을 필요할 때만 실리는 곳으로 옮긴다        | 없음                           | A1 전역 → 프로젝트 · A2 상시 지시문 → rules(경로·조건부) · A3 상시 지시문 → 스킬 · A4 MCP를 프로젝트 단위로·지연 로딩으로 |
| **B. 중복 없애기**   | 같은 지시가 여러 곳에 있거나 에이전트 기본 동작과 같다 | 없음                           | 전역·프로젝트·rules에 같은 문장, 시스템 프롬프트가 이미 하는 말                                                           |
| **C. 설정으로 대신** | 프롬프트 문장을 에이전트 설정 키로 바꾼다              | 없음(설정 키가 같은 효과일 때) | 응답 언어를 지시문 대신 설정으로                                                                                          |
| **D. 개인 추천값**   | 사용 패턴에 맞춰 조절 값을 추천한다                    | 목표에 따라 다르다(품질↔한도)  | 압축 시점, 추론 effort·최대치, 스킬 수, 모델                                                                              |
| **E. 끄기**          | 플러그인·MCP·스킬을 끈다(0014)                         | 있음                           | 최근 N일 한 번도 안 부른 MCP                                                                                              |

- A~C는 "최적화" 화면(팝오버 자리, 나중에)에 들어간다. D는 개인 기준이 있어야 한다. E는 대시보드 "진단하기"로 옮긴다.
- E는 사용 기록 근거가 있을 때만 제안한다(예: 최근 N일 호출 0회, N은 tuning). 근거가 없으면 목록에만 둔다. Claude는 0022로 근거를 읽는다. Codex·Kiro는 끄기 근거가 없어 제안하지 않는다(2026-11-13, 0022). Codex MCP는 코드 모드 호출 기록으로 "프로젝트에서만 켜기"만 제안한다(2026-11-19, 0022 "Codex MCP").
- 새 아이디어가 A~E 어디에도 안 맞으면 유형을 추가하고 이 표를 고친다.

### 화면 문구 — 사용자 결정 2026-11-06

kcal의 몫은 점검 결과를 해석해 주는 것이다. 설정을 모르는 사용자가 "뭔 소리지… 좋아지겠지, 해 줘"로 넘어가게 두지 않는다.

- 제목은 설정 이름이 아니라 사용자가 겪는 일로 쓴다. 예: "가끔만 필요한 규칙이 매번 실려요".
- 카드는 세 질문에 남김없이 답한다. **무엇을 하나 / 내 것 중 무엇이 바뀌나(빠지는 것이 누구 것인가) / 누가 하나(kcal·나·Claude)**. 좋아지는 것(한도 아끼기·말 잘 듣게·기억 지키기)과 고를 것(있으면 선택지)을 함께 쓴다.
- 잃는 것은 사용자 기록으로 좁혀 하나만 보인다. 예: 옛 모델에만 먹는 설정은 최근 N일(tuning) 쓴 모델을 보고 "잃는 것 없음" 또는 "그 모델의 high가 풀림" 중 하나.
- 설정 키·파일 경로·공식 문서 링크·diff는 0009 "자세히" 안에만 둔다.
- 통과 시험: 설정을 모르는 사람이 카드만 읽고 남는 질문이 없어야 한다. 첫 시험(2026-11-06, 사용자)에서 세 장이 떨어졌다. 기억 메모 카드는 "지우는 거야, 키우는 거야?"(할 일 없음), 커밋 카드는 "내 거 버리는 거야?"(누구 것이 빠지나 없음), 긴 CLAUDE.md 카드는 "어떻게 줄여?"(방법 없음).

## 개인 기준 ("몸짱"의 기준) — 사용자 결정 2026-11-06

- **기본값 = 표준 몸짱**: kcal 기준 + 공식 문서 권장(예: CLAUDE.md를 어떻게·얼마나 쓰라고 하는지). 목표를 따로 정하지 않은 사용자는 이 기준으로 본다.
- **목표 정하기(대시보드)**: 사용자가 기본값에서 출발해 자기 목표를 고친다. 목표를 정하는 과정에서 자기 사용 방식을 알아 가게 하는 것이 목적이다. 선택지 예: 한도 오래 버티기 / 답 품질 우선 / 빠른 응답 / 최소 변경(구체 선택지는 첫 점검을 만들며 정한다).
- **고정**: 항목마다 "나 이거 써"를 표시하면 E에서 빠진다.
- **패턴**: 이미 재는 값을 입력으로 쓴다. 세션 길이, 압축 횟수, 요청당 입력(0013·0016), 하루 사용량(0015).

## 적용 방식 — 사용자 결정 2026-11-06

- 설정 값 하나를 켜고 끄는 E는 0014 방식(미리보기 → 백업 → 적용 → 되돌리기)을 그대로 쓴다.
- **기계적 변경은 kcal이 0014 방식으로 직접 한다**(사용자 결정 2026-11-06. 같은 날 정한 "A~C는 diff와 복사 명령만"을 바꾼다). 대상은 규칙 파일 맨 위에 `paths` 한 줄 붙이기, 파일 옮기기, 설정 값 하나 바꾸기다. 이유: 일반 사용자는 "명령 붙여 넣기"에서 막힌다(읽기 시험의 "부탁해!").
- **글을 고쳐 쓰는 변경(CLAUDE.md 줄이기 등)은 kcal이 쓰지 않고 Claude에게 맡긴다**(사용자 결정 2026-11-06). 사용자가 버튼을 누를 때만 kcal이 Claude Code를 모델 `claude-opus-5-5`, effort `medium`으로 고정해 한 번 실행한다. 낮은 모델은 이 일을 제대로 못 할 수 있어서 고정한다. 버튼 바로 아래에 "한도를 씁니다(남은 한도가 있어야 실행)"와 지금 남은 한도를 **반드시** 적는다.
  - 제안(확인 필요): 실행은 읽기 전용으로 고쳐 쓴 글만 받는다. 적용은 diff 미리보기 → 0014 방식으로 한다. 남은 한도가 기준(tuning) 아래면 버튼을 끈다. 프로세스 실행은 `src-tauri/src/usage/sources.rs`의 `run`(타임아웃·`kill_on_drop`)을 재사용한다. 새 실행 경계라 구현 전에 결정 기록을 따로 쓴다.

### 첫 점검 (Codex) — 2026-11-21

- **카드**: `D-codex-fast-mode`(D, Codex 탭 한 장, 안내만). 사실표 행 D `/fast`·`service_tier`·`features.fast_mode`와 측정 행(Fast 배수)이 근거다(Codex 사실표 11-21: facts 158·161~163·174·246·253~254·302).
- **판정**(파일만 읽는다): 사용자 `~/.codex/config.toml`의 최상위 `service_tier = "fast"`이고, `[features].fast_mode`가 `false`가 아니고(없으면 문서 기본 on), `forced_login_method`가 `api`가 아니고, `~/.codex/auth.json`이 ChatGPT 로그인이다(없거나 ChatGPT가 아니면 카드 없음. 로그인 종류만 꺼내고 토큰 값은 어디에도 두지 않는다). 배수는 최상위 `model`로 상수 표에서 찾는다: GPT-6.2 Astra·Sol 2배, GPT-6.1 Sol·Terra와 GPT-6 Astra·Sol·Luna 2.5배, 그 밖이나 미설정은 숫자 없이 "더 써요". 문서 수치(확인 2026-11-21)라 tuning에 두지 않는다.
- **할 일과 누가**: 안내만. 사용자가 Codex에서 `/fast`를 한 번 더 입력하면 Standard로 돌아가고 Codex가 선택을 저장한다. kcal은 파일을 쓰지 않는다. `apply_check`가 이 옵션을 받으면 기존 "적용할 수 없는 옵션" 거부 경로를 그대로 탄다.
- **잃는 것**: 응답 생성 속도. GPT-6.2 Astra는 문서에 Standard보다 약 1.5배 빠르다고 있어 그 모델만 숫자를 말하고, 다른 모델은 숫자 없이 쓴다. 전체 완료 시간이 그 비율로 변한다거나 정확히 얼마를 아낀다고는 쓰지 않는다.
- **추천을 Standard로 둔 이유**: kcal은 한도 앱이고 개인 목표 설정이 아직 없어서 kcal 기본 기준을 따른다. `keep` 옵션은 카드에 있지만 화면에 "그대로 두기" 버튼은 없다(숨기기는 추천이 `keep`인 카드에만 있다). 그래서 일부러 빠른 모드를 쓰는 사용자는 이 카드를 숨길 수 없다. 추천을 "그대로"로 바꾸면 숨길 수 있다(사용자 결정, 보고서 2026-11-21).

- 숨김 규칙: id가 숨긴 목록에 있고 **지금도 추천이 `keep`**일 때만 숨는다. 판정은 Rust(`CoachCheck.isDismissed`, `coach/checks/dismissed.rs` `mark`), 화면은 걸러서 보인다. 추천이 바뀌면(예: 규칙에 서명 줄이 생겨 C 추천이 "내 규칙만 남기기"가 되면) 목록에 id가 남아 있어도 다시 나온다.
- 저장: kcal 안에만. `app_data_dir()/check-dismissed.json`(coach-log와 같은 폴더)에 id 문자열 배열. `WRITE_LOCK` 아래 temp→rename으로 쓴다. 읽을 때 깨졌거나 모양이 다르거나 상한(id 512바이트, 64개)을 넘으면 빈 목록으로 보고 로그를 남긴다. 설정 파일은 건드리지 않고 적용 기록도 남기지 않는다.
- command(프론트는 id만 보낸다):

| command                   | 입력 | 동작                                                                                                                            |
| ------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------- |
| `dismiss_check`           | `id` | 판정을 다시 돌려 그 id가 있고 추천이 `keep`일 때만 저장. 아니면 `invalid_input`. 이미 있으면 그대로 성공. 64개가 차 있으면 거부 |
| `restore_dismissed_check` | `id` | 그 id 하나를 목록에서 뺀다(2026-11-18, 전에는 모두 비우는 `restore_dismissed_checks`)                                           |

- 화면: 숨긴 카드가 있으면 목록 끝에 "숨긴 카드 {n}개" + 보조 버튼 "보기". 누르면 숨긴 카드 제목을 펼쳐 보여 주기만 하고, 카드마다 "다시 알리기"(`restore_dismissed_check`)로 하나씩 돌린다(2026-11-18 사용자 요청: 한 번 누르면 전부 올라와 헷갈림). 모든 카드가 숨으면 "지금 고칠 것이 없어요." 아래에 같은 줄. 쓰기 뒤 `get_checks`를 다시 읽는다(polling 없음). 문구는 `check-copy.ts`.
- 정한 것: 목록에서 지금 판정에 없는 id도 지우지 않는다(카드가 사라졌다 같은 추천으로 돌아오면 숨긴 채로 둔다). 숨긴 목록은 다시 알리기로만 줄인다.

### 적용 기록 이름 (2026-11-07)

- 점검 기록은 `name`이 이미 행동 이름("생각 깊이 옛 설정 정리")이라, 화면은 `target`이 `claude/check:`(Rust `coach::checks::CHECK_TARGET_PREFIX`, TS `ipc.ts` 같은 이름)로 시작하면 이름만, 아니면 기존대로 "<이름> 켬|끔"을 보인다(`check-copy.ts` `appliedName`). 코칭 "최근 바꾼 것"·완료 패널 기본 제목·0016 처방 효과가 같이 쓴다. 되돌림 제목 "<이름> 되돌림"은 그대로.
- 이를 위해 `health::PrescriptionEffect`에 `target`(`AppliedSwitch.target`)을 더했다. 위 "알려진 한계"의 "<이름> 끔" 항목은 이것으로 풀렸다.

### 구조

- 대시보드 머리("kcal 대시보드" 줄) 아래 탭 두 개: **사용량**(전 대시보드 내용 그대로) / **점검**(`src/components/checks-tab.tsx`). shadcn `Tabs`를 쓴다. 날짜 선택은 사용량 탭에서만 보인다.
- 점검 탭: 켠 에이전트(`settings.enabledAgents` 순서)마다 사용량 탭 에이전트 칸과 같은 모양(아이콘 + 이름)의 칸 하나. 칸 안은 `md` 이상 두 열, 좁으면 위아래.
  - 왼쪽 "최적화": 그 에이전트의 `CoachCheck` 카드(`checks-view.tsx` `AgentChecks`). 문구·버튼·자세히·"그대로 두기"는 그대로. 미리보기 → 확인 → 완료·되돌리기는 그 카드 자리에서 하고 다른 카드는 그대로 보인다. 적용 뒤 다시 읽은 목록에서 카드가 빠져도 완료 패널은 그 자리에 남는다. 보이는 카드가 없으면 Claude는 "지금 고칠 것이 없어요.", 점검이 없는 에이전트는 "{이름}는 아직 최적화 점검이 없어요."
  - 오른쪽 "진단하기"(E, 0014): 그 에이전트 스위치만(`coach-view.tsx` `CoachPanel`). 동작은 그대로이고, "효과 보기"는 사용량 탭으로 바꾼 뒤 "처방 효과"로 스크롤한다.
  - "숨긴 카드 n개 · 보기"는 탭 맨 아래 한 번.
- 데이터: 점검 탭을 열 때 `get_checks`·`get_switches`·`get_coach_log`를 읽고, 적용·되돌리기·숨김·다시 알리기 뒤 다시 읽는다. 사용량 탭은 숨겨도 마운트를 유지해(다시 읽지 않음) 탭을 오가도 무겁지 않다.
- 팝오버: 메뉴의 "진단하기"·"최적화" 두 줄과 두 화면(뒤로 가기 머리, 높이 상한 스크롤)을 지우고 "점검" 한 줄을 둔다. 누르면 `open_dashboard("checks")`.

### 알림 개수

- 개수 = 켠 에이전트의 카드 중 `!isDismissed && 추천 옵션 id ≠ "keep"`인 것(`check-copy.ts` `alertCount`). 팝오버 개요 탭은 켠 에이전트 전체를, 에이전트 탭은 그 에이전트 카드만 센다(사용자 결정 2026-11-07: Kiro·Codex 탭에 Claude 카드 점이 떠서 헷갈림). 꺼 둔 에이전트의 카드는 대시보드에 안 보이므로 세지 않는다(구현하며 정함).
- 개수가 `checkAlertMin` 이상이면 "점검" 옆에 빨간 점 + 숫자(`aria-label` "점검할 것 {n}개"). 아니면 아무것도 붙이지 않는다.
- 진단하기(E)는 세지 않는다. 0022가 Claude 끄기 제안의 기준(30일·10세션)을 정했지만, 그것은 "문제"의 기준이 아니라 "쓰는지 알 수 있다"의 기준이라 알림 수에는 여전히 세지 않는다. "문제"라고 할 기준(위 "열린 것"의 2차 "14일·10세션")은 아직 없다.
- 팝오버는 처음 한 번과 창이 포커스를 받을 때(`focus` 이벤트, 열 때마다) `get_checks`를 다시 읽는다. 무거운 기록 읽기는 Rust 캐시(TTL `metricsTtlSecs`, 기본 5분)라 대부분 즉시다. 앱 시작 때 `coach::checks::prewarm`이 뒤에서 한 번 캐시를 데운다(반복 없음).

## 갱신 2026-11-28: 서브에이전트 effort 카드

### 확인한 사실

- [Choose an effort level](https://code.claude.com/docs/en/sub-agents#choose-an-effort-level): agent의 `effort` 필드·호출별 인자로 깊이를 정할 수 있다. 따로 정하지 않았다면 `CLAUDE_CODE_EFFORT_LEVEL`, 부모 서브에이전트나 이번 턴의 effort, `CLAUDE_CODE_SUBAGENT_EFFORT` 순으로 적용한다. 이것들이 없고 메인과 같은 모델이면 세션의 effort를 따른다(2026-11-28 문서 확인).
- [환경변수 표](https://code.claude.com/docs/en/env-vars): `CLAUDE_CODE_SUBAGENT_EFFORT`는 low·medium·high·xhigh·max를 받는 기본값이다. forks·forked skills·teammates에는 적용하지 않는다. 현재 문서는 2.1.315 이상으로 표기한다(intent의 changelog 기준은 2.1.316).
- transcript의 최상위 `effort`·`attributionAgent`와 파일 경로를 읽는다. 본문을 보관하지 않고 기존 파일별 `(mtime, size)` 파싱 캐시를 공유한다. 기존 모델·사용량 출력은 바꾸지 않는다.

### 결정과 이유

- 카드 id는 `D-claude-subagent-effort`. 기존 `checkModelDays`와 같은 `since` 이상인 assistant 요청 중 경로에 `subagents` 디렉터리가 있는 파일만 센다. `message.id` 중복과 synthetic 응답은 기존 모델 집계처럼 뺀다.
- xhigh·max 요청이 1건 이상이고 사용자 settings `env`에 두 effort 변수가 모두 없을 때만 제안한다. high까지 문제로 삼지 않으며 새 tuning은 추가하지 않는다. 기준을 낮추면 high 대 medium 차이까지 다룰 수 있지만 이번 범위에서는 제외한다.
- 품질 우선으로 추천 기본값은 `high`다. `set-high`는 사용자 settings의 `env.CLAUDE_CODE_SUBAGENT_EFFORT` 한 값만 적고, keep·미리보기·백업·되돌리기는 기존 경로를 쓴다. 새 세션부터 적용되는 것으로 안내한다.
- IPC 사실은 days·heavyRequests·subagentRequests·byEffort·agents·recommended다. byEffort는 알려진 단계별 요청 수를 깊이순으로 보낸다. effort 누락·알 수 없는 값도 전체 요청 수에는 포함하므로 단계별 합계와 전체가 다를 수 있다. agent 이름은 xhigh·max 요청에서만 모아 정렬하고 화면에는 최대 5개와 나머지 개수를 보인다.

### 범위와 한계

- frontmatter의 `effort`나 호출별 effort는 바꾸지 않는다. 부모·이번 턴의 effort가 우선할 수도 있어서 모든 xhigh·max 요청이 줄어든다고 보장하지 않는다. 토큰 비용 절감량을 계산하지 않는다.
- project/local·managed settings와 실행 중인 프로세스·shell 환경변수는 조사하지 않는다. 사용자 settings만 대상으로 한다. forks·forked skills·teammates는 설정의 적용 대상이 아니며, transcript 파일 위치만으로 이들을 구분해 효과를 보장하지 않는다.
