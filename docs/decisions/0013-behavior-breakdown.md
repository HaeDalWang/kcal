## 결정

| 결정                                                                                                                                                                                                                                                                              | 이유                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 창 구성 `CodexRate.composition`(Rust `rate::behavior`): 기간 요청(0008 정의)을 창으로 묶고 `window_row` 합(입력에 캐시 포함)을 1%당 토큰으로 나눈다. 입력 몫 = 캐시 + 비캐시 항, 출력 몫 = 출력 항. 계수 0인 항은 0                                                               | 창 하나의 실측 사용 %와 바로 비교된다                                               |
| 고르는 창 = 요청 수 중앙값 창(짝수면 아래쪽). 세 몫·예상 합·실측 %가 같은 창의 값                                                                                                                                                                                                 | 몫마다 중앙값을 내면 합이 어떤 창과도 맞지 않는다                                   |
| 시작 설정 몫 = 프론트 `compositionOf`의 `windowShare(시작 합계, 창 패턴 중앙값 N·M)`. 대화 누적 = 입력 몫 − 시작 설정, 음수면 0(`ponytail:`). 시작 토큰을 모르면 "입력" 한 조각                                                                                                   | "세션 시작 토큰 (약 2.5%)" 줄과 같은 숫자여야 한다(고른 창 N·M이면 2.9%로 어긋났다) |
| 세션 `CodexRate.sessions` = rollout 파일. 요청 수, 평균 입력, 캐시 미스, 요청별 몫 합. 몫 큰 순 `topSessions`개만                                                                                                                                                                 | 여러 창에 걸치면 100%를 넘는다. 화면에 "5시간 한도 % 합"                            |
| 세션 이름: 첫 줄 `session_meta`의 `cwd` 마지막 폴더(`/`·`\`). 기존 읽기 루프에서 첫 줄만 접두 검사 후 파싱. 없으면 파일 이름의 시작 시각                                                                                                                                          | 파일 재열기 없음. 첫 줄 약 22KB × 48개                                              |
| 배지 "긴 세션"(요청 ≥ `marathonRequests`), "큰 컨텍스트"(평균 입력 ≥ `largeContextTokens`)는 Rust가 판정                                                                                                                                                                          | 기준을 tuning 한 곳에                                                               |
| 환율이 `estimated`가 아니면 `composition: null`, `sessions: []`. 이벤트는 `compute()`가 읽은 것 재사용                                                                                                                                                                            | 0003 표기 규칙, 재읽기 없음                                                         |
| Kiro "한 턴 ≈ 월 한도의 X%" = `creditsPerTurn ÷ (limit / 100)`(TS `kiroTurnShare`), 한도는 usage month 창 `limit`. 없으면 숨김                                                                                                                                                    | 측정 ÷ 측정이라 `~` 없음. 새 IPC 없음                                               |
| Claude 변경 없음. 환율 회귀는 5시간 창 20개 이상 기록 뒤. 기준은 tuning에 두지 않음                                                                                                                                                                                               | 회귀 코드가 없다. 넣을 때 `minSamplesPerVar` 재사용 여부를 정한다                   |
| 화면: 트레이 Codex 탭에 구성 막대(에이전트 색 100·70·45% 명도, 한도 100% 기준) + 범례 "(예상)", 많이 쓴 세션(이름·날짜·배지·요청·~%, 자세한 값은 hover). Kiro 탭에 모델 3개 크레딧/턴과 몫. 대시보드에 검증 줄 "실제 68% · 예상 65%", 세션별 값, Kiro 모델별 몫. 값이 없으면 숨김 | 0009·0011 틀. 새 컴포넌트 `behavior-section.tsx`                                    |

## tuning (0007 방식)

| JSON 필드            | 기본값  | 범위              | 의미                         |
| -------------------- | ------- | ----------------- | ---------------------------- |
| `topSessions`        | 3       | 1 ~ 20            | 많이 쓴 세션 수              |
| `marathonRequests`   | 150     | 10 ~ 10,000       | "긴 세션" 요청 수            |
| `largeContextTokens` | 130,000 | 1,000 ~ 2,000,000 | "큰 컨텍스트" 평균 입력 토큰 |

근거(이 Mac 최근 14일 세션 46개, 로컬 조사 기록(비공개)): 요청 수 p50 81 · p75 144 · p90 240, 평균 입력 p50 113K · p75 130K · p90 139K. p75 근처로 반올림. 09 마라톤 규칙(200)보다 낮은 것은 상위 4분의 1 표시용 배지라서다.

## 실측 (이 Mac, 2026-11-05, `codex_behavior_on_real_rollouts`)

- 환율(추정): 1% ≈ 캐시 1.92M · 비캐시 67K · 출력 2.8K.
- 보통 창(20개 중, 요청 274 · 미스 7): 입력 27.3% + 출력 37.7% = 예상 65.1% vs 실제 68%. 그중 설정 2.5%(12,006 토큰), 대화 누적 24.8%.
- 상위 세션(모두 `project-a`): 10/30 요청 421 · 평균 입력 126K · ~175%(긴), 11/03 277 · 135K · ~92%(긴, 큰), 11/04 244 · 139K · ~69%(긴, 큰).
- Kiro(월 10,000 크레딧): auto 0.0083% · sonnet-5.5 0.099% · opus-5.5 0.18% · opus-5 0.39%.
- 09 "약 90%는 활동"보다 더 크다: 예상 65% 중 설정은 약 4%, 96%가 대화 누적·답변. 답변이 입력보다 큰 것은 출력 1%당 토큰이 작아서다(추론 토큰 포함으로 보임, 확인 안 함).
