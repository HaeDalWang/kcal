# 0022. 진단하기: 사용 기록 근거와 프로젝트에서만 켜기

- 상태: 채택(구현함, 2026-11-13)
- 날짜: 2026-11-13
- 앞선 결정: [0014](0014-coaching.md) 스위치 적용·되돌리기, [0017](0017-optimization-framework.md) "E는 사용 기록 근거가 있을 때만", [0007](0007-tuning.md) tuning. 백로그 9-1·11.

## 문제

진단하기는 토큰 크기만 보고 끄기를 권했다. 30일에 47번 쓴 플러그인을 1순위로 끄자고 했고(2026-11-10), 동료가 "쓰는 건데 왜 끄라고 해?", "프로젝트 단위로는 못 나눠?"라고 물었다(2026-11-13).

## 사실 (2026-11-13, Claude Code 2.1.323, macOS, 임시 폴더에서 확인)

- `claude plugin disable <id> --scope local`: 그 폴더 `.claude/settings.local.json` `enabledPlugins.<id>: false`. 그 폴더 세션에서만 꺼지고 다른 폴더는 켜진 채다(세션 init 플러그인 목록으로 확인).
- `claude plugin enable <id> --scope local`: 사용자에서 끈 플러그인이 그 폴더에서만 켜진다. CLI는 `~/.claude/plugins/installed_plugins.json`에 local 항목도 넣지만, 그 항목 없이 `settings.local.json`만 있어도 실리고 세션이 항목을 스스로 넣는다. → kcal은 두 settings 키만 쓴다.
- 하위 폴더에서 시작한 세션은 그 폴더와 git 루트 양쪽의 `.claude/settings.local.json`을 읽는다.
- 세션 기록의 줄 `cwd`는 `cd`를 따라 바뀐다(한 파일에 최대 49개). 파일의 첫 `cwd` = 시작 폴더 = 기록 폴더 이름(231개 중 230개).
- 사용 표시: assistant 줄 `tool_use` 이름 `mcp__plugin_<이름>_<서버>__*`·`mcp__<서버>__*`, `Skill` `input.skill`·`Agent`/`Task` `input.subagent_type`의 `<이름>:`, user 줄 `<command-name>/<이름>:…`. `api-request-blob` 줄은 요청 다시 적기라 세지 않는다.
- 자세한 기록: 작업 폴더 `evidence/facts.md`(커밋하지 않음).

## 알려진 한계

- 플러그인 이름이 바뀌면 옛 이름의 사용은 세지 않는다(이 Mac `team-skills` → `team`).
- 훅·LSP만 있는 플러그인은 쓰임이 기록에 안 남는다. 끄기 제안은 시작 토큰이 있는 것(스킬·MCP)만이라 지금은 겹치지 않는다.
- "범위"의 프로젝트 값은 최근 N일 안에 세션을 시작한 폴더만 본다. 하위 에이전트 기록은 그 파일의 첫 `cwd`를 쓴다.
- `.claude/settings.local.json`이 git에 안 잡히는지는 그 사람 gitignore에 달렸다(Claude가 넣어 주지 않는다, 확인됨).

## 갱신 2026-11-14: "프로젝트에서만 켜기"의 근거

사건: 30일·227세션 중 플러그인 스킬 1회(한 프로젝트)만으로 "프로젝트에서만 켜기"가 제안됐다. 사용자는 자주 쓴다고 느꼈고 화면에 근거가 없어 kcal을 믿을지 몰랐다. 접두사 없는 `/<스킬>` 명령은 플러그인 사용으로 세지 않아(`command_key`가 `:`를 요구) 실제 사용이 더 적게 잡혔다.

| 결정                                                                                                                                                                                                                                                                                                     | 이유                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 제안 조건에 `total >= scopeMinUses`(tuning, 기본 3, 1~1000)와 `sessions >= diagnoseMinSessions`를 더한다. 모자라면 제안하지 않는다                                                                                                                                                                       | 1~2회로는 자주 쓰는지 알 수 없다. 끄기 제안(0회)과 같은 세션 기준. 3은 "한 번 써 본 것"과 "쓰는 것"을 가르는 값으로 정했고 실측으로 고른 값이 아니다(설정으로 조절) |
| `SwitchUsage`에 `scopeMinUses`, `lastUsed`(초, 없으면 null), `lastProject`를 더한다. `lastUsed`는 키·프로젝트별 가장 늦은 줄 `timestamp` 중 최댓값                                                                                                                                                       | 화면이 근거 한 줄과 "횟수가 적다" 문장을 Rust와 같은 값으로 만든다                                                                                                  |
| 줄: "1 use in 227 Claude sessions over 30 days · last used Nov 5 in side-app". 사용자 범위로 켠 플러그인이 `scopeMinUses` 미만이면 "Too few uses to suggest a project-only scope"를 덧붙인다. 출처("Claude 세션 기록에서 kcal이 센 값")는 진단하기 맨 위 설명에 한 번만 쓴다                             | 공식 문서의 기준이 아니라 kcal 계산이라는 점을 밝힌다. 예전 프로젝트별 횟수 목록은 줄에서 빼고 마우스를 올린 설명(경로 + 횟수)으로 옮겼다                           |

한계: 프로젝트 폴더가 지금 없으면 그 폴더의 `.claude`는 확인하지 못해 같은 이름이 있어도 플러그인으로 센다. 플러그인을 지웠거나 이름을 바꿨으면 옛 명령은 세지 않는다.

## 갱신 2026-11-19: 스킬 단위(개인·프로젝트)

진단하기가 플러그인·MCP만 다뤄서, 안 쓰는 개인·프로젝트 스킬의 설명이 매 세션 실려도 줄일 길이 없었다(백로그 "진단하기 개선" 5).

사실(확인됨, 2026-11-19, 공식 문서): <https://code.claude.com/docs/en/skills> "Override skill visibility from settings". `skillOverrides.<스킬 이름>`은 `"on"`(이름+설명 나열), `"name-only"`, `"user-invocable-only"`(Claude에게는 숨김, `/` 메뉴에는 남음), `"off"`(어디서나 숨김)를 받고, 없으면 `"on"`이다. 플러그인 스킬에는 영향이 없다. 키는 사용자·프로젝트·local 설정에서만 스킬 이름과 맞는다.

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |

한계:

- 프로젝트 스킬은 가장 최근 세션의 작업 폴더 하나만 본다(진단하기의 기존 작업 폴더). 다른 폴더의 스킬은 목록에 없다.
- 개인 스킬의 다른 프로젝트 설정(`settings.json`·local)에 있는 `skillOverrides`는 읽지 않는다. 사용자 설정과 최근 작업 폴더의 두 파일만 본다.
- 줄이는 토큰 양을 모른다. `~/.claude/commands/<이름>.md`(옛 명령)는 대상이 아니다.
- `skillOverrides` 값이 실제로 시작 목록에서 설명을 빼는지는 문서 기준이다. 새 세션 스킬 목록으로 직접 확인하지 않았다(추정 → 확인 방법: 숨긴 뒤 새 세션에서 `/context`의 스킬 목록).
