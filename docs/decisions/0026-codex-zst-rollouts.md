# 0026. 압축된 Codex rollout(`.jsonl.zst`)도 읽는다

- 상태: 채택
- 날짜: 2026-11-18
- 앞선 결정: [0003](0003-product-scope.md)·[0004](0004-usage-and-tray.md) "열린 것"의 `.jsonl.zst` 건너뛰기

## 문제

Codex는 열흘쯤 지난 rollout을 `.jsonl.zst`로 압축한다(이 Mac 실측: 11/08 이전 103개 압축, 11/09 이후 47개 그대로). kcal은 `.zst`를 건너뛰어 Codex 1%당 토큰과 지표가 최근 열흘 남짓만 보았다. 환율이 측정 시점마다 크게 달랐던 원인으로 보인다(백로그 "측정·표시").

## 결정

- `rate::codex`의 rollout 목록에 `rollout-*.jsonl.zst`를 넣고, 읽을 때 zstd를 풀어 같은 줄 단위 읽기를 쓴다. 지표(metrics)도 같은 목록을 쓴다.
- 해제는 순수 Rust `ruzstd`(0.9.1, MIT)를 쓴다. C 라이브러리를 빌드하지 않아 Windows CI에 짐이 없다. 표준 라이브러리·기존 의존성에는 zstd 해제가 없다.
- 압축 머리가 깨진 파일은 빈 파일로 보고, 중간에 깨지면 그 앞 줄까지만 쓴다.
- 시작 컨텍스트 실측(`context::codex_session`)은 가장 최근 세션만 열어 압축 파일이 해당하지 않으므로 그대로 둔다.

## 결과(실측, 2026-11-18 이 Mac)

|     | 파일 | 이벤트 | 5시간 창 | 검증 R² |
| --- | ---- | ------ | -------- | ------- |
| 전  | 47   | 3,385  | 17       | 0.95    |
| 후  | 154  | 19,745 | 103      | 0.87    |

창이 6배가 되어 값이 덜 흔들릴 것으로 본다(추정, 확인 = 며칠 뒤 다시 재서 비교).

## 위험

- 환율 계산마다 압축 파일 103개(압축 347MB, 풀면 825MB)를 푼다. release 실측으로 읽기+적합이 0.12초에서 3.05초가 됐다(백그라운드, 계산은 `ratesTtlSecs` 기본 30분마다·새로고침 때만). 지표(metrics)는 수정 시각이 막대 기간 안인 파일만 읽어 압축 파일은 거의 열지 않는다. 더 줄이려면 백로그 "2층 환율: 파일별 증분 캐시"(압축 파일은 다시 바뀌지 않아 캐시가 잘 맞는다).
