# 0010. 트레이는 결론만, 자세한 것은 대시보드 창

- 상태: 채택(구현함, 2026-11-05)
- 날짜: 2026-11-05
- 앞선 결정: [0009](0009-ui-plain-language.md)(쉬운 말·디자인 틀). 0009의 "자세히"는 트레이에서 빼고 대시보드로 옮긴다.

## 원칙

사람은 해석하기 싫어서 이 도구를 깐다. 트레이를 열면 숫자를 읽는 순간 뜻이 들어와야 한다. 통계·근거·항목 목록처럼 해석이 필요한 것은 전부 대시보드에 둔다.

## 트레이(팝오버)

개요 탭은 지금 그대로 둔다. 에이전트 탭 하나는 위에서 아래로 이렇게 구성한다.

1. **사용량**: 지금 바 그대로.
2. **지표 3줄**(글머리표, 한 줄에 하나):
   - `세션 시작 토큰: 12k 토큰 (약 2.1%)`. %는 Codex처럼 계산할 수 있는 에이전트만 붙인다.
   - `최근 5시간 요청: 42회`
   - `캐시 적중률: 92%`
3. **막대 그래프**: 최근 5시간 구간별 사용량.
4. **메뉴**(모든 탭 공통, 세로 목록): 대시보드 / 진단하기 / 새로고침 / 설정 / 종료.

값을 모르는 줄은 "—"로 채우지 않고 줄을 숨긴다. `~`나 툴팁 말고는 트레이에 설명 문장을 두지 않는다.

## 지표 정의

| 지표            | 정의                                                                | Codex                                    | Claude                                                                       | Kiro                                                                              |
| --------------- | ------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 최근 5시간 요청 | 지금 5시간 한도 구간(`resetsAt − 5h` ~ 지금) 안의 요청 수           | rollout 이벤트(반복 보고 제외, 입력 > 0) | `~/.claude/projects/**/*.jsonl`의 assistant `usage`. 같은 `message.id`는 1회 | 5시간 한도가 없어서 최근 5시간(지금 기준)의 질문(turn) 수. 라벨 "최근 5시간 질문" |
| 캐시 적중률     | 같은 구간의 토큰 기준: 캐시에서 읽은 입력 ÷ 전체 입력               | `cached / input` 합                      | `cache_read / (input + cache_read + cache_creation)` 합                      | 기록에 없으면 줄 숨김                                                             |
| 막대 그래프     | 최근 5시간 구간마다 그 구간 안에서 가장 큰 사용 %. 지금 구간을 강조 | rollout `used_percent`                   | `limit-history.jsonl` 5시간 기록                                             | 5시간 구간이 없어서 최근 7일 일별 크레딧                                          |

- 구간 수, 일 수, Claude 로그 탐색량은 `tuning`에 넣는다(0007 규칙).
- 계산은 Rust에서 하고, 기존 캐시 방식(0005·0006: 마지막 값 즉시 반환, 오래되면 뒤에서 갱신 + event)을 따른다. polling을 새로 만들지 않는다.

## 대시보드 창

- 두 번째 창 `dashboard`. 시작할 때 만들지 않고 메뉴를 누를 때 Rust command가 만들거나 보여 준다. 크기는 바꿀 수 있고 장식(제목 표시줄)이 있다. 열면 팝오버는 닫는다.
- 내용: 0009의 "자세히"에 있던 것 전부를 에이전트별로 넓게 보여 준다. 1%당 토큰과 토큰 종류별 값, 사용 패턴 통계, 세션 시작 토큰 항목 목록, 질문당 크레딧이 여기에 들어간다.
- capability: `default.json`의 `windows`에 `dashboard`를 추가한다. permission은 `core:default` 그대로이고 새 plugin은 없다.

## 버튼

- **새로고침**: command 하나가 사용량 조회(기존 429 backoff는 지킨다)와 1%당 토큰·세션 시작 토큰·새 지표의 재계산을 바로 시작한다. 결과는 기존 event로 화면에 반영된다.
- **진단하기**: 5층 코칭 자리다. 지금은 비활성으로 두고 툴팁에 "준비 중"을 단다.

## 이유

- 사용자 요청(2026-11-05): "해석이 아니라 주입". 사용자가 트레이 배치를 직접 정했다.
- 사용자 선택(2026-11-05): 캐시 적중률은 토큰 기준, 요청 수는 지금 한도 구간 기준, 그래프는 구간별 사용량, 대시보드는 별도 창.
- Kiro에 5시간 한도가 없어서 같은 자리에 가장 가까운 값을 넣는다(최근 5시간 질문, 일별 크레딧).

## 구현 (2026-11-05)

- Rust: `src-tauri/src/metrics/`(`get_metrics` command, `metrics-updated` event, `MetricsState` 캐시, 시작 때 `prewarm`). IPC 타입 `MetricsSnapshot`·`AgentMetrics`·`UsageBar`·`BarUnit`, TS 짝은 `ipc.ts`의 같은 이름. fixture `metrics-snapshot.json`.
- `refresh_all`(`lib.rs`): 조회 타이머에 새로고침 표시를 남기고 깨운다(`usage::schedule::request_refresh`). 환율·시작 컨텍스트·지표는 TTL 0으로 `Cache::get`을 불러 뒤에서 다시 계산한다(이미 계산 중이면 그 결과 event를 기다린다).
- `open_dashboard`(`tray.rs`, async): 있으면 보여 주고 포커스, 없으면 `WebviewWindowBuilder`로 900×700(최소 560×400), 크기 조절·제목 표시줄. 팝오버는 숨긴다. 같은 `index.html`을 쓰고 `main.tsx`가 창 label로 `Dashboard`를 고른다.
- `fit_popover_height`는 `popover` 창에서만 받는다(대시보드에서 부르면 `invalid_input`).
- 트레이 에이전트 탭: `AgentSection` → `MetricLines` → `UsageBars`. `RateLine`·`ContextList`(와 `InfoSection`의 자세히)는 대시보드에만 있다. 대시보드에서는 자세히를 접지 않고 늘 보이며 세션 시작 토큰 항목을 전부 보인다.
- tuning(0007 표): `metricsTtlSecs`(5분), `recentBars`(8), `barDays`(7), `claudeLogFiles`(50).

## 명세와 다르게 한 것

- **Kiro 일별 막대는 달력 날짜가 아니라 지금부터 거꾸로 자른 24시간 구간**이다. Rust `time`에 지역 시간대 기능(`local-offset`)이 꺼져 있고 의존성을 바꾸지 않기로 했다. 툴팁은 다른 막대처럼 "MM/DD HH:mm 시작 · N 크레딧"(지역 시각).
- **지금 구간을 모르면 요청 수·캐시 적중률 줄을 숨긴다.** Claude·Codex 모두 마지막 구간의 리셋이 이미 지났으면(아직 새 구간 기록이 없음) 값을 내지 않는다. Claude 지금 구간은 한도 기록(`limit-history.jsonl`, API 조회가 성공할 때마다 씀)에서 찾는다.
- **지금 구간은 마지막 묶음 하나뿐이다.** 이 Mac Codex 기록에서 09:14 리셋 구간이 04:23에 끝나고 04:44에 09:44 리셋 구간이 시작됐다(한도가 일찍 초기화됨). 리셋이 안 지난 구간이 둘이어도 강조와 요청 수는 마지막 것만 쓴다.
- **막대 기간 상한**: Claude·Codex 막대도 최근 `barDays`일 안의 구간만 그린다. Codex는 그 기간에 바뀐 rollout만 읽어 계산량을 줄인다(환율 계산은 여전히 전체를 읽는다).
- **새로고침 간격**: 같은 에이전트를 30초(`REFRESH_MIN_GAP`)보다 자주 조회하지 않는다. 직전 조회가 429였으면 늘어난 간격을 그대로 둔다.
- Codex 캐시 적중률은 요청마다 `min(cached, input)`으로 더한다(캐시가 입력보다 크게 보고되는 줄 대비).
- "세션 시작 토큰" 숫자는 화면의 다른 토큰 값과 같은 표기(`12K`)를 쓴다.
