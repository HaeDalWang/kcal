# 0009. UI 쉬운 말과 디자인 틀

- 상태: 채택(화면 확인 전)
- 날짜: 2026-11-05
- 범위: 팝오버 전체(개요·에이전트 탭·설정). 계산식·IPC·Rust는 바꾸지 않는다. 기존 결정 0004~0008의 화면 문구를 이 문서가 대신한다.

## 디자인 틀

섹션 하나 = 아래 네 단계. 위 두 단계만 보고도 뜻이 통해야 한다.

1. **제목**: 쉬운 말(아래 용어 표).
2. **큰 값 한 줄**: `text-sm font-medium`, 숫자 하나가 주인공.
3. **설명 한 줄**: `text-xs text-muted-foreground`, 일반 사용자 말.
4. **자세히**: 네이티브 `<details>`(JS 상태 없음). 통계(p90, R², 범위, 표본 수), 토큰 종류별 값, 측정 방식은 여기에만 둔다.

신뢰도 표기: 예상 값은 숫자 앞에 `~`, 정확(측정) 값은 아무것도 붙이지 않는다. 값 위에 `title`로 "예상: 기록으로 계산한 값" / "정확: 측정한 값". 기본 화면에 "실측·추정·추론" 글자를 쓰지 않는다.

`%p`는 쓰지 않고 `%`로 쓴다. 남은 %, `4h 35m` 같은 시간 표기는 그대로 둔다.

## 계산 (표시용, 새 식 없음)

- **1%당 토큰(한 숫자)** = `N / windowShare(1, N, M, perPercent)`. 0008의 식을 그대로 뒤집은 것: 보통 5시간 구간(요청 N, 캐시 미스 M)에서 입력 토큰 1개가 차지하는 평균 %의 역수. 출력 토큰은 빠진다(자세히에 따로). 창 패턴이 없으면 캐시 입력 값만 보여 주지 않고 "계산 중/기록 부족" 상태 문구.
- **캐시되지 않은 요청 %** = `misses.median / requests.median`. 중앙값끼리 나눈 근사라 자세히에 적는다.
- "평균" 대신 "보통"(중앙값).

## 이유

- 사용자 요청(2026-11-05): 값 나열 느낌, 일반 사용자가 모르는 말이 많다.
- 사용자 예시 "첫 세션에 소비되는 토큰 1,024 = 2.1%"에서 %는 한 번 쓰는 양이 아니라 요청마다 다시 실려 5시간 동안 쌓인 몫(0008)이다. 그래서 설명 문구에 "요청마다 다시 실려서"를 넣었다.
- `<details>`는 브라우저 기본 기능이라 새 의존성·상태가 없다.
